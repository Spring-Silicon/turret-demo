# SAM 3.1 v18

The combined dropdown maps **SAM 3.1 v18** to:

- Arc: `sam3.1-v18`, Israel's full1008 native v18 Object Multiplex tracker.
- Thor: `sam3.1-tracking`, the shared unquantized BF16 Inductor implementation
  with CUDA graph replay. It is the same implementation used by the ordinary
  Tracking choice, not a CUDA port of Israel's quantized/token-reduced v18.

This is an additional choice, not a replacement for SAM 3.1 Tracking. It keeps
the same live session lifecycle, mask output, centroid targeting, hold/reacquire
policy and prompt controls. Selecting a model does not itself arm the motors.
Opening or reloading the page does not change either backend's model.

## Differences and qualification

V18 retains 1008x1008 input, mask decoding and temporal tracking, but uses
INT4 image projections, INT8 heads, half the spatial temporal KV tokens, and
75% MLP tokens in selected image blocks. V18 adds native QKV/RoPE and direct
attention-output quantization to the earlier recipe. Graph replay is used for
warmed region shapes; unfamiliar temporal shapes use direct execution under
the existing bounded-cache policy.

It is **not dense-accuracy-equivalent**. Source eager validation covers 545
frames/15 person scenes (81.7292% mask IoU, 72.3605% box IoU). Compiled crossing
and lucia clips completed; these are not a full live-camera or full compiled
accuracy qualification. Keep the original Tracking option for comparison.

Deployment smoke test on spring-edge-turret (2026-09-09): 80 recorded frames
completed, with fresh image processing on every frame, valid temporal IDs and
mask output. Image/detection and temporal graph replay were observed. The last
16 frames had median model-region latency 134 ms and full worker latency
152.075 ms; these are recorded football-scene timings, not a paired benchmark
against the original tracker or a dense-accuracy qualification.
